# 升级与兼容性

本页区分仓库中原来的 0.0.9 实现与当前尚未发布的可靠性修复。`package.json` 的版本号尚未调整；不要据此认为新修复已经发布到 npm。

## 保持不变

- 导出名、构造函数与 `request(config, expiredTime, retry, retryDelay)` 的参数顺序。
- `instance`、`getDefaultConfig()`、`setDefaultConfig()`，以及宽松的 `Promise<any>` 返回类型。
- POST 合并、普通错误缓存、首次调用策略、零 TTL 分发窗口。
- 默认最多重试 9 次、普通 4xx/5xx 重试、固定延迟与负延迟取绝对值。
- 结果共享原始对象引用，TTL 从分发时计时。
- 重置配置替换默认值，实例模式重建实例并重置拦截器。

## 修复的行为差异

| 场景 | 原 0.0.9 实现 | 当前仓库实现 |
| --- | --- | --- |
| 负 TTL、非实例模式 | 可能丢失默认配置 | 使用完整合并配置 |
| 表单、二进制、函数配置 | JSON 序列化可能遗漏信息 | 按内容或身份生成键 |
| 直接修改实例默认请求头 | 缓存键未反映变化 | 实例默认配置参与键 |
| 取消请求 | 可能重试或缓存取消错误 | 不再重试取消，不长期缓存 |
| 已取消 signal 命中缓存 | 可能返回成功缓存 | 拒绝为取消结果 |
| 实例配置更新失败 | 原配置可能已被覆盖 | 保留原配置与实例 |
| 不合法重试次数 | 可能形成不受控次数 | 约束为有限非负整数 |

这些修复确实改变了有问题的行为，不宣称所有执行语义与旧版完全相同。

## 已有项目如何升级

1. 在测试环境安装待发布的新版本，保持当前 Axios 版本。
2. 检查认证头、租户切换、拦截器返回值与 `setDefaultConfig()` 后的重新注册逻辑。
3. 检查所有写操作是否需要独立执行，以及是否允许重试。
4. 验证普通失败缓存、取消结果和缓存命中的业务处理。
5. 通过应用集成测试后灰度升级。

## 验证依据

当前仓库提供新旧源码对照测试、TypeScript 调用兼容性检查与 ESM/CJS 发布产物检查。库入口和核心源码的语句、分支、函数、行覆盖率均达到 100%，并设置同样的检查门槛。

```sh
npm run check
```

100% 源码覆盖率不等同于覆盖所有应用环境。详细测试结果以运行命令生成的报告为准。文档构建不会改变库的运行时 API。
