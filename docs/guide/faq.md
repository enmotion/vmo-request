# 常见问题

## 缓存时间为 0 为什么只发送一次？

0 关闭的是已完成结果的长期缓存，保留等待中的请求合并。分发窗口结束后条目删除；后续请求重新发送。每次都要独立执行，请使用 -1。

## 为什么第二次调用仍然失败？

正 TTL 会缓存普通失败结果。有效期内不会自动刷新。降低 TTL，或使用负值独立执行。取消错误在当前修复中不长期缓存。

## 这是状态管理或洋葱中间件框架吗？

当前公开 API 是请求包装器。内部维护请求状态，但没有状态订阅、`use()` 或 `next()` 中间件组合接口。`RequestProps.middlConfig` 是供应用使用的数据字段。

## 可以跨标签页或跨服务器进程合并吗？

不可以。缓存和并发协调仅属于当前 VmoRequest 实例。没有分布式锁或持久化存储。

## 可以手动清空缓存吗？

当前没有公开的清空接口。需要完全独立的缓存空间时创建新实例；只想绕过缓存时使用负缓存时间。

## 结果会深拷贝吗？

不会。合并者和缓存命中者共享原始结果引用。

## TypeScript 返回值为什么是 any？

为了兼容已有响应拦截器返回业务数据的用法。应用可以在自己的接口层声明返回类型；库目前没有 `request<T>()` 泛型接口。

## 文档和 npm 包的行为为什么可能不同？

当前站点描述仓库实现，包括尚未发布的可靠性修复。请核对[升级说明](./upgrade)，不要把文档站上线等同于 npm 新版本发布。
